# Career Evidence: fictional worked example

From reader Chapter 32. Connect a claim to permitted evidence, contribution and observed/proposed/simulated status. These are proposed or illustrative teaching records, not actual agreements or outcomes.

| Claim candidate | Evidence anchor | Status and honest wording |
|---|---|---|
| “Designed an R7 explanation boundary.” | Fictional capstone memo, negative semantic test and receipt-only API example. | **Simulation.** “Designed in a documented teaching case”; no live implementation claim. |
| “Aligned cross-functional owners.” | Meeting record with actual owner acceptance, if an employer permits use. | **Conditional work evidence.** If only proposed, say “facilitated a dependency discussion”; do not claim adoption. |
| “Reduced deployment time 80%.” | Before/after timestamp method, release scope, team attribution and permission to disclose. | **Observed only if evidence exists.** Explain whether the number measures lead time, build time or deployment execution, and what else changed. |
| “Used AI responsibly.” | Permitted-input statement, bounded tools, versioned prompt/source, independent checks, human decision and fallback. | **Process evidence.** Add a measured outcome only when separately established. |
| “Improved learner starts.” | Approved baseline and follow-up with population, method, confounders and organizational permission. | **Unknown in Harbor.** Do not put this result on a resume from a fictional exercise. |
