# Architecture Decision: fictional worked example

From reader Chapter 18. Make context, viable alternatives, status, consequences and revisiting conditions inspectable. These are proposed or illustrative Harbor records, not actual agreements or outcomes.

| Field | Fictional proposed R7 decision |
|---|---|
| Status and date | Proposed, October 26, 2026. No institutional sign-off or release. |
| Question | Which path should Harbor evaluate first to help learners understand a receipt event while preserving R7 meaning, access, accessible help and sustainable operation? |
| Context | The current assistant produces staff-reviewed drafts only. No approved budget, observed comprehension baseline, accepted Support receiving capacity or completed per-learner access demonstration is in this fictional packet. Receipt and satisfaction are distinct. |
| Option A | Correct approved static wording on the existing delivery path and preserve the authorized human route. Low new operational coupling; may become hard to maintain if legitimate case variation is high. |
| Option B | Add a bounded staff-reviewed AI draft using current approved source/version and learner-specific read access, with expert review, stop, evaluation and fallback. May help varied cases; adds model, retrieval, review, privacy, cost and correction work. It cannot send or write independently. |
| Option C | Let an agent decide satisfaction or create cases automatically. Rejected for current consideration: missing policy delegation, authorized action contract, receiving capacity and demonstrated recovery. |
| Proposed decision | Evaluate A first. Treat B as a separate later experiment only if source, access, review burden, Support capacity and wrong-guidance controls are evidenced and accepted by their owners. Do not implement C under this direction. |
| Tradeoff and confidence | A is simpler and reversibly improves wording, but may not cover genuine variation. Confidence is moderate about fit as a first test, low about learner benefit until tested. No invented threshold or ROI is claimed. |
| Consequences and dependencies | Policy must approve wording and negative cases; Support must accept the receiving path; Security must verify object access; operations and release owners must accept stop/exposure. Engineering may choose implementation and run synthetic checks but cannot infer those acceptances from a green build. |
| Revisit and history | Revisit when new R7 policy, affected-person feedback, exception rate, staff correction burden or sustained route load changes the assumptions. If the direction changes, create a new ADR that supersedes R7-01 and links to the evidence; do not rewrite the old rationale. |
